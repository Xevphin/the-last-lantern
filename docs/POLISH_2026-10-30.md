# Combat, animation and visual polish

This pass preserves the existing playable project and uncommitted work on `dev-world`. The pre-polish snapshot is `.delivery-backup/before-polish.zip`. No commits, pushes, merges or music were added.

## Changes

- Sword damage uses a short forward physics query immediately and throughout its 140 ms active window. Enemy hurtboxes use dedicated layer 4 (mask value 8). Existing overlaps work; a per-swing target set prevents duplicate damage. Walls still block attacks. Movement direction is read before starting an attack, then locked for that swing. The visible slash follows that direction. Recovery remains 150 ms.
- Player art increased from 0.375× to 0.5×; regular enemy art from 0.5× to 1×. Body collision shapes and map geometry are unchanged. DIVESH uses a 64×80 pixel texture displayed at 2×, with a foot-aligned visual offset and his original 64×64 body collision.
- DIVESH now has distinct armored humanoid artwork, charcoal/purple armor, gold chest core and eyes. The generated source is `assets/characters/divesh_guardian.png`; Godot samples it onto a 64×80 grid with nearest-neighbor filtering. Original artwork remains in place.
- Limited procedural sprite animation provides breathing, walking bob/lean, attack lean, hit flash and a dissolving death echo. DIVESH also has separate charge anticipation/movement, shockwave preparation/impact, and exposed-core stun poses. These are procedural animations, **not** a full hand-animated directional sprite sheet. Gameplay state machines and damage rules remain intact.
- Player death shows the dissolution for 0.65 seconds before the retry overlay. Dead-player attack and movement restrictions remain in effect.
- Charge warnings show the charge corridor; shockwave preparation shows its danger circle. A soft arena light improves visibility. Boss status text is below the fight instead of covering his sprite.
- Main Menu reuses the existing dungeon corridor image behind its existing buttons. Village ambient brightness is increased; existing street lamps flicker gently and sparse motes drift. No exploration geometry or additional houses were added.
- Ending text is exactly **THE LAST LANTERN**, **GAME END**, **Wait for Updates**, with **MAIN MENU**. No timer or restart-to-village behavior remains. The button starts unfocused, so held gameplay accept input cannot activate it; clicking/tapping it or deliberately focusing with Tab returns to the existing Main Menu. Start Game resets progression.

## Validation

Run `python tests/progression/run_checks.py` from the project root. Eight suites cover:

1. Melee: 40 cases across eight directions and five distances, including existing overlap, one hit per swing, rear exclusion, range limit, walls, mid-swing entry, same-tick turn/attack, direction lock and pause.
2. Animation: distinct boss poses, core/hit shader parameters, unchanged body sizes, pixel-grid scaling, death echo creation and cleanup.
3. Existing Wanderer combat regression.
4. Burst, energy, cooldown and touchscreen Burst regression.
5. Keyboard movement, simultaneous touch joystick/sword, pause release and boss attack damage.
6. Live DIVESH duel using movement/sword/Burst input with boss AI active.
7. Main-map objective reachability using the real player collision shape.
8. Complete progression, ending persistence under held accept input, explicit Main Menu return, new-game reset and death/retry.

Rendered menu, village, DIVESH, restored Beacon and ending captures were inspected. They are in `tests/progression/reports`, alongside test logs. The renderer still reports the sandbox's unavailable user shader-cache folder, but renders successfully.

This verification is automated gameplay plus rendered visual inspection, not a new complete human-controlled playthrough or physical Android-device test. Extra village exploration decoration remains deferred as requested. Android SDK/templates remain unavailable from the previous delivery; this pass does not produce an APK.

## Artwork provenance

DIVESH was created using the built-in imagegen tool, with transparency, then copied into the project. Prompt: one full-body front-facing/slight-top-down dark-fantasy shadow-armored humanoid guardian; charcoal/purple articulated armor, distinct helmet/pauldrons/arms/separated legs, glowing gold eyes and diamond chest core, torn cloak, menacing crown-like horns; clean limited-palette pixel-art style; single centered neutral sprite, no weapon, floor, scenery, text, border or ground shadow. The game uses deliberate nearest-neighbor pixel sampling; the generated source is retained at full resolution.
